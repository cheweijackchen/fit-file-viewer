# TrailKit — Impeccable Design Context

## Design Context

### Users
Trail enthusiasts of all levels — from casual weekend hikers to regular peak baggers, with a focus on Taiwan's hiking community (百岳 / 100 Peaks). Users review their hike data after returning from the trail, wanting to relive the experience and track their progress. Job to be done: make sense of hike data (heart rate, elevation, GPS tracks) in a way that feels personal and connected to the outdoors — not clinical or corporate.

### Brand Personality
**Three words: Warm. Adventurous. Trustworthy.**

TrailKit feels like a knowledgeable trail companion — welcoming enough for first-timers, capable enough for serious peak-baggers. References: Strava (data clarity and athlete focus) + AllTrails (earthy warmth, trail community feel).

Anti-pattern: cold, clinical dashboards that feel like medical software or enterprise SaaS. No sterile whites, no heavy blues, no density-for-density's-sake.

Emotional goal: after viewing their hike data, users should *feel* the hike — not just see numbers.

### Aesthetic Direction
- **Tone**: Earthy and organic in personality; precise and clear where data is displayed
- **Color system**: Yellow (sunlight, energy, Mantine primary) as the brand accent; warm neutrals (Mantine gray/dark) as the foundation
- **Photography / imagery**: Mountain landscapes and trail photography are used on landing/marketing surfaces; inside the app, maps provide the visual "nature" element
- **Dark/light modes**: Both fully supported; dark mode evokes nighttime trail prep and post-hike review
- **Typography**: Inter (clean, legible UI text) + Noto Sans TC (Taiwan bilingual support) + JetBrains Mono (data values, coordinates, statistics)
- **Icons**: Tabler Icons — clean line weight appropriate for both outdoorsy warmth and precise data UI
- **Reference apps**: AllTrails (warmth, landing experience), Strava (data density done right in-app)

### Design Principles

1. **Outdoorsy soul, data clarity**
   TrailKit is fundamentally a data tool — charts, stats, and tables dominate most screens. The "outdoorsy" personality lives in the color palette, tone of voice, and iconography, not in photography competing with data. The map *is* the nature element; charts should be clear and information-dense, never sacrificing readability for aesthetics.

2. **Clarity under complexity**
   GPS tracks, heart rate zones, elevation profiles, peak lists — present these without overwhelming. Progressive disclosure: show the essential story first, let users dig into details on demand.

3. **Bilingual by default**
   English (en-US) and Traditional Chinese (zh-TW) are equally important. Typography, spacing, and layout should accommodate both scripts gracefully. Never break layouts for longer Chinese text.

4. **Earthy precision**
   Warm, organic aesthetics on the surface; precise, reliable data underneath. Like a well-crafted topographic map: beautiful AND accurate.

**Hard rules (from CLAUDE.md):**
- No hardcoded hex colors in JSX — use Mantine CSS variables or Tailwind classes
- Layout: Tailwind utilities only (no Mantine Flex/Stack for layout)
- Visual separation: Mantine Card/Paper components
- Styling priority: component props → Tailwind → SCSS modules → (avoid inline styles)

## Design System Constraints (Mantine 8.3.x)

### Color System

Mantine uses a **10-shade palette** per color (indices 0–9, lightest to darkest).

| Token | Usage |
|-------|-------|
| `--mantine-color-yellow-5` | Primary brand accent (CTA buttons, highlights) |
| `--mantine-color-gray-0` through `gray-9` | Light mode surface and text |
| `--mantine-color-dark-0` through `dark-9` | Dark mode surface and text |
| `--mantine-color-red-*` | Error states |
| `--mantine-color-green-*` | Success states |
| `--mantine-color-blue-*` | Info / link states |

Custom semantic text variables (light/dark aware):
- `--text-emphasis`: primary text
- `--text-secondary`: supporting text
- `--text-subtitle`: labels, captions
- `--text-muted`: disabled / placeholder text

**Rule**: Never use raw hex in designs. Reference Mantine color tokens or semantic CSS variables.

### Available Component Categories

Prefer Mantine components over custom ones. Avoid designing custom versions of these:

| Category | Components |
|----------|-----------|
| **Layout / containers** | Card, Paper, Container, Divider, Space |
| **Typography** | Text, Title, Anchor, Blockquote, Code, Highlight, Mark |
| **Buttons & actions** | Button (filled/outline/subtle/transparent), ActionIcon, CopyButton |
| **Forms & inputs** | TextInput, NumberInput, Select, MultiSelect, Checkbox, Radio, Switch, Slider, Textarea, FileInput |
| **Navigation** | Tabs, Breadcrumbs, Pagination, Anchor |
| **Overlays** | Modal, Drawer, Tooltip, Popover, HoverCard, Menu |
| **Feedback** | Alert, Notification, Progress, Loader, Skeleton |
| **Data display** | Badge, Avatar, ThemeIcon, Table, Accordion, Spoiler |
| **Charts** | AreaChart, BarChart, DonutChart, LineChart (via @mantine/charts / Recharts) |
| **Dropzone** | Dropzone (file upload with drag-and-drop) |

### Component Defaults (configured in theme)

- **Card**: padding `xl` (24px), radius `default`, border enabled
- **Paper**: radius `md` (8px), border enabled
- **Button primary**: variant `filled`, color `yellow`
- **Select**: checkmark positioned right
